## 1. Global design rules (SDD-04 §1) — apply to every migration

| # | Rule | Source reason |
|---|---|---|
| 1 | PostgreSQL **16+** is the single system of record (incl. job queue + outbox) | TRD-02, ADR-17 |
| 2 | Every tenant-scoped table: `tenant_id uuid NOT NULL` + RLS policy `tenant_id = current_setting('app.tenant_id')::uuid`; app role **cannot bypass RLS** | SEC-01, BR-SEC-04 |
| 3 | Money = `bigint` minor units + `currency char(3)`; rates = `numeric`; **no float/real/double precision anywhere** | BR-MNY-01, ADR-06 |
| 4 | History by effective dating (`valid_from`, `valid_to`); genealogy also recorded time (`recorded_at`, `superseded_at`); rows closed, never overwritten | GAP-010 |
| 5 | Financial and result tables insert-only: `UPDATE`/`DELETE` revoked from app role **and** blocked by trigger | BR-LED-02 |
| 6 | PKs = UUID v7 (time-ordered) generated by the application (no DB default — *inferred*) | index locality, tenant merge |
| 7 | Enums = `text` + `CHECK` | simple migrations |
| 8 | Standard columns on every table unless stated: `created_at timestamptz NOT NULL DEFAULT now()`, `created_by uuid` (not repeated in the per-table column lists below; add them unless the table already lists them) | audit |
| 9 | Brand and market dimensions from the first release | GAP-095, ADR-14 |
| 10 | Tax ids, identity documents, bank details never in plain columns: ciphertext with per-tenant keys, or document ref to separate encrypted store, plus masked display value | SEC-07 |
| 11 | Logical `order` → table **`sales_order`**; logical `case` → table **`case_file`** | SQL keywords |

Ownership: each table has exactly one owner module; other modules read via owner interface/read models and **never write** (SDD-04 §2). Owner codes below are from spec.json.

### 1.1 Required extensions and roles
- Extensions: `ltree` (path_node), `btree_gist` (EXCLUDE with `=` on uuid/text), `pg_trgm` (participant.display_name search). *Inferred from the constraints/indexes; not listed in source.*
- App role: `NOBYPASSRLS`; tables owned by a migration role; use `ALTER TABLE ... ENABLE ROW LEVEL SECURITY` **and** `FORCE ROW LEVEL SECURITY` (*recommended* so the owner is also subject).
- Migration test (BR-SEC-04, §6): **fails if any table with a `tenant_id` column lacks an RLS policy.**
- Session: tenant id taken from the authenticated session, set via `SET LOCAL app.tenant_id`, never from client input (BR-SEC-04).

### 1.2 RLS classes

| Class | Tables | Policy |
|---|---|---|
| Platform (no tenant data, no RLS) | `tenant`, `guardrail_rule`, `tax_rule`, `license_entitlement`, `update_log` | none; `guardrail_rule`/`tax_rule` read-only to app role (shipped in market packs) |
| Standard tenant | all other tables with `tenant_id NOT NULL` | `USING/WITH CHECK (tenant_id = current_setting('app.tenant_id')::uuid)` |
| Nullable tenant (shared platform rows) | `role` (base roles), `golden_dataset` (platform datasets) | SELECT: `tenant_id IS NULL OR tenant_id = current`; write: `tenant_id = current` |
| Nullable tenant (vendor realm) | `user_account` (vendor users, `tenant_id NULL`) | tenant rows as standard; vendor rows only via vendor-realm role |
| Separate store | `audit_event` | separate DB or schema; RLS on `tenant_id`; no FKs |

### 1.3 Mutability classes (summary)

| Class | Tables |
|---|---|
| **INSERT-ONLY** (revoke + trigger) | `approval`, `tenant_setting_version`, `audit_event`, `guardrail_decision`, `agreement_acceptance`, `order_line`, `run_snapshot`, `result_line`, `qualification_state`, `journal_entry`, `posting`, `tax_line`, `case_event`, `license_entitlement`, `update_log` (`approval` and `update_log`: insert-only is *inferred* — source states only the approver CHECK / "is the audit record") |
| Insert-only except one-time close | `relationship` (valid_to, superseded_at), `bank_detail_version` (superseded_at), `late_transaction` (consumed_by_run_id once) |
| Immutable after a state | `sales_order` (fact columns after insert), `import_mapping` (approved), `plan_rule`/`plan_transition` (parent version ≥ approved), `compliance_report_snapshot` (only → outdated), `participant_type` flags (once referenced by committed run) |
| Effective-dated, close via `valid_to` + EXCLUDE (source) | `participant_type_assignment`, `position_ownership`, `customer_servicing`, `tax_profile` |
| Effective-dated, close via `valid_to`, no EXCLUDE in source | `role_assignment`, `product_volume_map` (EXCLUDE *recommended* only) |
| Derived / rebuildable | `path_node`, `statement`, `cpl_fact_*`, `import_row_error`, `compliance_figure` |

Insert-only trigger template:
```sql
CREATE FUNCTION forbid_mutation() RETURNS trigger LANGUAGE plpgsql AS $$
BEGIN RAISE EXCEPTION '% on % is not allowed (insert-only)', TG_OP, TG_TABLE_NAME; END $$;
-- per table:
REVOKE UPDATE, DELETE ON <t> FROM app_role;
CREATE TRIGGER <t>_no_mutation BEFORE UPDATE OR DELETE ON <t> FOR EACH ROW EXECUTE FUNCTION forbid_mutation();
```

## 2. Database-enforced invariants (SDD-04 §6, verbatim mechanism)

| Invariant | Mechanism | Rule |
|---|---|---|
| Entry balances | Deferred constraint trigger on `journal_entry` comparing sums of its postings at commit | BR-LED-01 |
| No edit of postings, result lines, relationships (except close), audit events | Revoked privileges + `BEFORE UPDATE OR DELETE` triggers raising an error | BR-LED-02, BR-GEN-02 |
| One parent per kind per child at any valid time | `EXCLUDE USING gist (tenant_id WITH =, kind WITH =, child_position_id WITH =, tstzrange(valid_from, valid_to) WITH &&) WHERE (superseded_at IS NULL)` | ENT-05 |
| One committed run per period | Partial unique index `run(period_id) WHERE state = 'committed'` | ENT-13 |
| Idempotency | Unique indexes on idempotency keys: `journal_entry`, `payout_instruction`, `inbound_event`, `run` | BR-PER-06, BR-PAY-10 |
| Approver ≠ preparer | `CHECK (approver_id <> preparer_id)` on `approval` | BR-ADJ-02 |
| Tenant isolation | RLS on every tenant-scoped table; migration test fails if a `tenant_id` table lacks a policy | BR-SEC-04 |
| No cycles in `relationship` | Not declarative: checked in the write transaction under a per-tenant, per-tree advisory lock (SDD-08 §4) | ADR-03 |

## 3. Partitioning, retention, volume (SDD-04 §5)

Sizing is an **assumed** workload (gap audit 15 §2; replace with design-partner data, OQ-06): 2,000,000 positions; 3,000,000 orders/month; 600,000 payout lines/run.

| Table | Growth driver | Strategy |
|---|---|---|
| `result_line`, `sim_result_line` | lines per run (~1 KB with trace) | RANGE by period month; simulation partitions dropped after a retention setting |
| `posting` | 2–4 per payout line | RANGE by `posted_at` month; never dropped inside retention |
| `sales_order`, `order_line`, `order_event` | orders | RANGE by `credited_at` month |
| `audit_event` | all actions | separate DB or schema; partition by month; write-once storage for archives |
| `inbound_event`, `outbox_event`, `webhook_delivery` | traffic | partition by week; purge after idempotency window (setting; **proposed 35 days**) |
| `relationship` | one row per enrolment/change | not partitioned; partial index on current rows |
| `path_node` | one row per position per tree kind | rebuilt; versioned by `model_version` |
| `cpl_fact_*` | rows per imported batch | partition by tenant and batch (cheap supersede) |

PostgreSQL constraint: on a partitioned table every PK/UNIQUE must include the partition key. Several partition keys are not columns of the table and several unique keys omit them — see Conflicts C-1/C-2 for the required column additions.

## 4. Migration order and FK cycles

- Migrations forward-only, versioned, run per database (pooled and each dedicated tenant DB) by the pipeline; a migration rewriting an insert-only table is rejected in review (SDD-04 §7).
- **Release A migration** (20 tables): `tenant`, `market`, `tenant_setting_version`, `user_account`, `role`, `role_assignment`, `approval`, `support_session`, `audit_event`, `document`, `import_batch`, `import_row_error`, `import_mapping`, `cpl_fact_participant`, `cpl_fact_order`, `cpl_fact_payout_line`, `compliance_report_snapshot`, `compliance_figure`, `outbox_event`, `export_job`.
- **Release B** (50): every table tagged B in §5. **Release V1** (5): `credit_type`, `fx_rate`, `integrity_signal`, `license_entitlement`, `update_log`.
- Forward FKs across releases: `user_account.participant_id → participant` (A → B): add the FK in the B migration. `ledger_account.credit_type_id` has **no FK in source**; *recommended*: add `→ credit_type` in V1 (doc change needed).
- Circular FKs (create tables first, then `ALTER TABLE ... ADD FOREIGN KEY ... DEFERRABLE INITIALLY DEFERRED`):
  - `period.committed_run_id → run` ↔ `run.period_id → period`
  - `run.snapshot_id → run_snapshot` ↔ `run_snapshot.prior_state_run_id → run`
  - `import_batch.superseded_by → import_batch` (self)
  - `approval` is referenced by many tables but references only `user_account`; `case_file.approval_id → approval`; `position_ownership/relationship/customer_servicing/restatement/integrity_signal.case_id → case_file`.
- Logical → SQL names in every FK: `order` → `sales_order`, `case` → `case_file`.
- Published data model for tenant export (FR-INT-003) = this schema minus `outbox_event`, `inbound_event`, `webhook_delivery`, `path_node` and secrets; export column names = column names here.

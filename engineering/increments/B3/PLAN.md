### 2.4 Run preflight (one function used by POST runs and GET periods blockers)
Order: period committed/paid/closed → 409 PERIOD_COMMITTED; `now() < ends_at` → BEFORE_CUTOFF; no plan version (`plan_version_for_period`) → PLAN_VERSION_MISSING; then, only when the previous period of the calendar is **covered by a plan version** (`plan_version_for_period(previous) IS NOT NULL`): previous period not committed → PRIOR_PERIOD_OPEN; previous committed period without committed run → PRIOR_STATE_MISSING; sync (D-B3-10) → SYNC_BEHIND. **Chain start** (no prior state, no history): the calendar's first period, or a period whose previous period has no plan version (a calendar whose `first_period_start` precedes the plan's first `effective_from`; those uncovered periods stay `open`, never block, and often cannot be deleted because B2 orders reference them). T-B3-17 includes such a calendar.

### 4.2 SQL contracts (DB agent; STABLE/VOLATILE as stated; `SET search_path = public`)
- `plan_version_for_period(p_period uuid) RETURNS uuid` — STABLE, INVOKER: the calendar's plan's version with state IN ('scheduled','active','retired') and greatest `effective_from ≤ period.starts_at`.
- `plan_crediting_event(p_market uuid, p_at timestamptz) RETURNS text` — STABLE: crediting event of the version in force at p_at of a plan covering the market (same states), NULL when none (several plans covering one market: the most recent `effective_from` wins; documented).
- `placement_width_for(p_market uuid) RETURNS int` — STABLE: version in force now; NULL when none.
- `plan_rules_in_force(p_market uuid, p_at timestamptz, p_kind text) RETURNS TABLE (plan_version_id uuid, rule_key text, params jsonb)` — STABLE.
- `pln_due_activations() RETURNS TABLE (tenant_id uuid, plan_version_id uuid)` — SECURITY DEFINER, system realm only.
- `plan_version_simulated(p_version uuid) RETURNS boolean` — a completed simulation of kind `simulation` of the version with `simulation.content_hash = plan_version.content_hash`.
- `guardrail_rules_hash(p_version uuid, p_rule_keys text[]) RETURNS bytea` — STABLE: `digest(jsonb_agg(jsonb_build_object('rule_key', rule_key, 'kind', kind, 'params', params, 'calendar_id', calendar_id, 'reversal_policy', reversal_policy) ORDER BY rule_key)::text, 'sha256')` over the named rules of the version; NULL when a named rule no longer exists. CPL computes `content_sha256` with it (D-B3-17).
- `comp_late_catch_up(p_run uuid) RETURNS SETOF uuid` — VOLATILE, INVOKER, called by commit (D-B3-12): inserts `late_transaction (original_period_id = the run's period, handling 'adjust', state 'pending', effect_estimate shaped like ORD `recordLate`'s `EffectEstimate`)` for orders of the calendar's market with `credited_at` in the period whose id ∉ `run_snapshot.order_ids`, and events of the period's orders whose id ∉ `order_event_ids`; `ON CONFLICT DO NOTHING` on the B2 unique (order/event, period) indexes; returns the new ids.
- `comp_simulation_source(p_simulation uuid) RETURNS TABLE (calendar_id uuid, settings_version_id uuid, content bytea, lines jsonb)` — for golden-from-simulation (PLN).
- `guardrail_outstanding(p_version uuid) RETURNS TABLE (decision_id uuid, rule_id text, outcome text, reason text)` — **current** evaluations (`guardrail_rules_hash(version, detail.rule_keys) = content_sha256`) needing an override (blocked overridable) or acknowledgement/override (warned); used by PLN submit and COMP simulation flags.

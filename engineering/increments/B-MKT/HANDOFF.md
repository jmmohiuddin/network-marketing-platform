## 3. Contracts later increments rely on
- **Decisions:** D-BM-01..16 (PLAN §0); E-ADR-50 in `ARCHITECTURE_DECISION_LOG.md` points at them (written by the records step) and lists the build-time changes.
- **Packs:** rates, thresholds, tax years, tax-id formats, register and filing duties come only from immutable platform rows; a new value is a new row with a new id (migration). No tenant setting holds a tax value. IN-2026.0 must not ship in a migration until C-9 is confirmed.
- **Withholding:** call `tax_withholding_instructions(period)` (TX001 DETAIL JSON → 422 TAX_RULES_INVALID); store the instructions in the snapshot with their basis; commit compares them again under the market periods lock. Rate NULL = no duty (tax line 0, basis no_duty, rounding 'none' mapped to rate 0).
- **Year-end:** only `tax_generate_forms(market, year)` writes forms (nmp_app has SELECT only); TS code never inserts into `tax_form`/`tax_form_generation`. Refusals: TX001 first status reason → 422, TX002 → 409 GENERATION_BUSY, 23514 → 500 INVARIANT_FAILED. Filing export needs step-up, `no-store`, audit without values.
- **Grievances:** `received_at` cannot change after creation; escalation is a `case_event` 'escalated' with actor NULL and data {deadline}, once per deadline; a market's pack cannot change once a grievance exists (409 MARKET_REFERENCED).
- **Locale:** `SUPPORTED_LOCALES` is one list in `apps/api/src/lib/locale.ts` and `apps/web/src/features/portal/i18n` (equality tested); every portal string, error and nav label from the catalogue; staff UI stays English; never show an API `message` in the portal. `message()` takes a trailing logger.
- **New routes:** add a role-matrix probe and an isolation case (coverage tests fail otherwise). Portal client components must not import staff feature modules or the catalogue index (statement bundle guard test).

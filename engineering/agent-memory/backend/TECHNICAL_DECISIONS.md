## API foundation, T-A02..T-A04 (2026-11-12)
- **Envelope** `{data, meta}` / `{error:{code,message,details,request_id}}` (task + PROJECT_ENGINEERING_CONTEXT), not RFC 9457 of API.md 2.1. X-Request-Id on every response; incoming X-Request-Id ignored.
- **Idempotency**: key per (tenant, key, `METHOD route-pattern`), hash = SHA-256 of canonical {params, body}; replay returns the stored status + body and header `Idempotent-Replayed: true`; different request -> 422 IDEMPOTENCY_KEY_REUSED (task; API.md says 409 IDEMPOTENCY_CONFLICT); a concurrent duplicate blocks on the key row until the first commits (then replays) or rolls back (then runs): no in-progress state exists, so no 409 (review R1 removed the dead branch and `replayBody`). MFA routes take no key (would store the TOTP secret).
- **Initial password = one-time invitation token** (user_invitation, SHA-256 only, TTL INVITATION_TTL_HOURS=72, re-issue revokes old). Since review R1 the token is minted by the job `iam.send-invitation` and exists only in the invitee's mail (never in an API response, job payload or log), so the inviting admin cannot set the invitee's password. created_by = inviter.
- **BR-SEC-05 read as dual control**: a grant is effective at once only if the role is not privileged AND the granter holds all its permissions over every requested market (granter's marketScope null, or a superset of the request; a request for all markets needs unscoped holdings); otherwise it becomes a role_grant_request a different admin approves with step-up. Strict reading made Compliance officer, Finance approver, Payout officer, DPO ungrantable (Tenant admin lacks their permissions in the SDD-10 matrix). Approver = neither preparer nor grantee (422 SOD_SELF_APPROVAL). Role creation is not a grant: any catalogue permission allowed.
- **Privileged** = holds any of user.manage, settings.manage, vendor_access.decide, mapping.approve, plan.activate. MFA roles = SEC-03 union (Tenant admin, Finance approver, Payout officer, Compliance officer, DPO, all vendor users); custom roles get MFA if privileged or participant.unmask.
- **Implementation consultant** = import.manage + mapping.edit (SC-24/25 personas); Support agent, Integration = no A permission. Audit export needs audit.read + export (Compliance officer only; Tenant admin searches but does not export).
- **Sign-in**: tenant by slug in the body (stands in for the sign-in hostname); unknown account verified against a dummy argon2 hash; one generic 401 INVALID_CREDENTIALS; 5 failures in 15 min -> 429 SIGN_IN_LOCKED for existing and unknown accounts alike; attempts while locked are not counted. Each attempt reserves its failure row under a per-key advisory lock before argon2 (R1), so the limit holds under parallel requests. Tenants in provisioning/archived refuse sign-in. MFA code failures use the same counter shape (key mfa:<user>) -> 429 MFA_LOCKED.
- **Sessions**: cookie `nmp_session` (32 random bytes base64url; SHA-256 stored), HttpOnly, SameSite=Strict, Secure unless COOKIE_SECURE=false (default true, R1), Path=/; token rotated (same row, new token_hash) when MFA elevates the session to AAL2. Per request: auth_find_session (system) then one realm tx: idle check (revoke when idle), user active + tenant not archived (else revoke; mitigates BUG-004 app-side), active grants. Permissions are reloaded every request, so role changes apply immediately.
- **MFA gate**: roles need MFA and not enrolled -> 403 MFA_ENROLMENT_REQUIRED; enrolled and session unverified -> 403 MFA_VERIFICATION_REQUIRED; routes opt out with `config: { allowPendingMfa: true }` (me, MFA, sign-out). Verification sets aal2, mfa_verified_at, step_up_at. TOTP 160-bit seed sealed with AES-256-GCM, AAD = user id; window +-1 step; last_used_step consumed by a conditional UPDATE.
- **CSRF**: X-Requested-With required on every POST/PUT/PATCH/DELETE, public ones included (login CSRF). No CORS.
- **Audit writer**: tenant, actor, request id, support session come from tx settings (`app.actor_type`, `app.request_id`, `app.support_session_id`, set by runInTenant/runInVendor); before_ref = JSON(before), after_ref = JSON({after, reason}). Nil UUID system actor stored as NULL. No audit schema change (adding columns would break existing chain hashes).
- **Jobs**: pg-boss schema installed by 0008 as owner (nmp_app has no DDL); create_queue SECURITY DEFINER so enqueue can create a queue; 0008 drops pgboss first because --reset leaves it. `enqueue(tx, job, payload)` sends inside the caller's tx (job exists only on commit) and reads the tenant from the tx (deviates from the requested enqueue(name, payload, {tenantId}): tenant never passed by a caller). Worker validates {tenantId, payload} and runs in runInTenant as actor 'system'.
- **Settings**: each version stores the full settings map (snapshot); write = latest map + key. If-Match required (428 / 412, ETag = latest version). effective_from optional, never in the past, never before the latest version's. Step-up for privacy.breach_contacts. Audit references the version, not values (personal data).
- **Audit export**: POST pins rows with max_seq (same CSV every download), export_job destination = tenant region, refusal above cap is committed and audited (EXPORT.REFUSED) then answered 422 EXPORT_ROW_CAP_EXCEEDED; download only by the requester, every row watermarked, formula cells prefixed with '.
- **Base roles** seeded by 0007 from renderBaseRoleSeed(); permissions.test.ts pins the text; resetTestDb truncates role, so API tests reseed with resetApiDb().
- Rate limiting: @fastify/rate-limit in memory: per session (IP when signed out) API_RATE_LIMIT_PER_MINUTE=600; sign-in routes use two `createRateLimit` counters (per IP, per tenant:email), SIGN_IN_RATE_LIMIT_PER_MINUTE=10 each, global limiter off for them.

## Review fixes R1 (2026-11-12)
- **login_attempt is a system-realm exception to "audit in the same transaction"**: it has no tenant (unknown accounts must be counted too), is reachable only through auth_* SECURITY DEFINER functions, and is written in its own withSystem tx; the matching AUTH.* audit event goes to the account's own realm log in a separate tx. Unknown accounts are not audited (no tenant log). Suggest an E-ADR entry.
- **Session revocations by the platform** (idle, user inactive, tenant archived) are audited in the revoking tx with actor_type system, actor_id NULL; resolveAuth's realm tx now runs as the system actor with the request id.
- **Mail drop**: lib/mailer.ts writes RFC 5322 files (0600) to MAIL_DIR; header values stripped of CR/LF. Stand-in for the SMTP transport TR-CON-11 names (same shape as E-ADR-13's local FileStore).
- **Admin-loss serialisation**: per-tenant advisory lock `iam.admins:<tenant>` taken first in assertAdminRemains; later statements under READ COMMITTED see the earlier tx's commit.
- **Grant validity**: valid_to must be in the future (zod, 400); approving a request whose valid_to passed -> 422 GRANT_EXPIRED (checked with the database clock); rejecting it stays allowed.

## T-A08/T-A09 IMP (2026-11-12)
- **Synchronous validation** in POST /v1/imports (201, not API.md's 202 + async): batch inserted as `uploaded` with all results, then moved to validated|rejected in the same tx (both audited: IMPORT.UPLOADED, IMPORT.VALIDATED|REJECTED). Files are written to the FileStore only for validated batches, just before commit; a failed request removes them.
- **Idempotency for multipart**: request.body is set to {fields, sha256 per file} before idempotent(), so the key's hash covers the file contents.
- **Sync errors**: 400 FILE_MISSING {files}, 413 FILE_TOO_LARGE {max_bytes}, 415 UNSUPPORTED_MEDIA_TYPE (not multipart), 415 UNSUPPORTED_FILE_TYPE (part not text/csv, application/csv, text/plain, application/vnd.ms-excel), 422 MARKET_UNKNOWN (also out-of-scope market), 400 VALIDATION_FAILED (period).
- **Row codes**: FORBIDDEN_COLUMN, SCHEMA_MISMATCH, DUPLICATE_KEY, ORPHAN_REFERENCE, INVALID_VALUE, OUT_OF_RANGE, REFUND_EXCEEDS_AMOUNT, NOT_PSEUDONYMOUS (participant_id containing '@', never echoed). row_no = spreadsheet line (header 1). Cells trimmed; headers matched case-insensitively. At most 10,000 findings stored (report.error_count has the total).
- **Validation additions**: duplicate line_id, payout month format, order/payout month within declared period (refund_month only format), day 1..days-in-month and required (order_date is NOT NULL), is_starter_kit 0/1, refunded <= amount, forbidden tokens + national/nationalid/taxid. Orphan tolerance = 0 (no setting exists). Raw purpose/source_kind codes accepted; mapping translates.
- **Warnings**: PARTICIPANT_TYPES (always), SPONSOR_NOT_IN_FILE, REFUND_WITHOUT_MONTH. The prototype's 25%/20% share warnings were dropped (no shipped thresholds); the load's data_quality gives exact counts.
- **Period**: YYYY-MM in/out; stored period_from = first day, period_to = last day of the month.
- **Mapping JSON**: {participant_types: {code: {counts_as_end_customer, can_earn}}, purposes: {code: purpose}, source_kinds: {code: source_kind}}; no implicit identity mapping. Unmapped purposes/source kinds load as 'unknown' and are listed in data_quality.unmapped; every participant type must be mapped (422 MAPPING_INCOMPLETE). The tenant has one mapping series (versions), PUT on the collection with If-Match (mirrors settings) instead of API-03's `PUT /v1/import-mappings/{id}`.
- **Mapping approval** = mapping.approve + step-up (C-4) + approver != author (422 SOD_SELF_APPROVAL) + `approval` row (object_type import_mapping, factor_verified_at = step_up_at); MAPPING.APPROVED audited. 409 MAPPING_ALREADY_APPROVED.
- **Attach** (validated|mapped -> mapped): 422 MAPPING_UNKNOWN / MAPPING_NOT_APPROVED / MAPPING_INCOMPLETE; wrong state 409 IMPORT_STATE_CONFLICT {state}.
- **Load**: batch row lock, then advisory lock `imp.load:<tenant>:<market>`; 422 BREACH_CONTACT_REQUIRED without privacy.breach_contacts; stored files re-hashed and re-validated (mismatch = 500, tx rolled back, batch stays mapped); facts via unnest bulk inserts (bigint as decimal strings); counts and sums re-read from the facts and compared to validation (mismatch = 500); overlapping loaded batches of the same market superseded (IMPORT.SUPERSEDED each), IMPORT.LOADED. CPL's 0030 triggers on import_batch outdate snapshots in the same tx. tenant.region lock is the existing 0004 trigger.
- **Market scope** (AC-36.2): batch routes filter by marketScope(import.manage); source-values by the union of scopes over import.manage/mapping.edit/mapping.approve. Mappings are tenant-wide.

## IMP review fixes R1 (2026-11-12) — supersedes the lines above where they differ
- **Stored = projection**: a validated upload is stored as the published columns only, re-serialised (every field quoted, cells trimmed); files jsonb per file = {sha256, size_bytes of the upload, stored_sha256 of the stored bytes}. Load compares stored_sha256. Extra columns never reach disk.
- **Forbidden header** = any word (camelCase split), adjacent pair joined, whole header joined in FORBIDDEN_WORDS, or containing email/phone/address/bank/iban/passport/birth; plus an extra column whose first 100 values include an email address.
- **Supersede by containment**: loaded batches whose period lies within the new period are superseded; any loaded batch that overlaps and reaches outside -> 409 IMPORT_PERIOD_OVERLAP, nothing changes. Checked before facts are written.
- **AC-40.1 owner = CPL (0031, trigger on import_mapping INSERT)**: IMP adds no snapshot logic. 0021/0022 are a withdrawn pair (net no-op).
- **Ids**: every id copied into facts must not contain '@' (NOT_PSEUDONYMOUS) and is <= 200 chars; codes (type, purpose, source_kind, is_starter_kit) <= 100 chars; > 1000 distinct codes per vocabulary = file-level INVALID_VALUE (row_no null). quote() never echoes a value containing '@'.
- **Starter kit**: is_starter_kit is a partner code; source_values.starter_kits counts non-empty codes; mapping `starter_kits: {code: boolean}` (optional, default {}); '', '0', '1' keep the published meaning unless named; other unmapped codes -> 422 MAPPING_INCOMPLETE details {starter_kits: [...]}. details lists only non-empty vocabularies.
- **Import gate**: one upload or load at a time per process (import-gate.ts), else 429 IMPORT_BUSY + Retry-After 10. Default IMPORT_MAX_FILE_BYTES 10 MiB. UPLOAD_DIR relative paths resolve against apps/api.

## T-A05/T-A06/T-A12 ops, support, prv (2026-11-12)
- **Cross-realm vendor actions in one transaction** (`inVendorThenTenant`): vendor part in the vendor realm, then the same tx switches app.realm/app.tenant_id to the affected tenant. Both audit logs (FR-OPS-001 "vendor log, and tenant log when tenant-affecting") and tenant-side rows commit atomically; no new policy or SECURITY DEFINER function needed. Deviates from "realm fixed per tx"; confined to support/vendor-tx.ts. Suggest an E-ADR (or a `withVendorThenTenant` in @nmp/db).
- **No new table** (db tests pin the table and policy sets): vendor idempotency lives on the created row (tenant / support_session: idempotency_key + request_hash, UNIQUE (creator, key)), INSERT ... ON CONFLICT DO NOTHING then replay. Replay returns the current representation, not a stored body.
- **Provisioning**: tenant row (vendor realm) + markets ('live': operating markets of an existing business), first admin (user_account invited + Tenant admin assignment, created_by = vendor user, no approval row: approval FKs need tenant users) and TENANT.CREATED/USER.INVITED/ROLE.GRANTED in the new tenant's log, one tx. Second-person approval = a different vendor user with step-up (tenant.created_by vs caller; the vendor-log event is the approval record) -> implementation + first-admin invitation job. Go-live implementation -> live needs a breach contact in force. Archive (FR-TEN-005) not built (V1).
- **Placement**: region catalogue constant {eu, ap-south-1, ap-south-2}, pooled only (no per-tenant database here) -> 422 REGION_UNAVAILABLE / TIER_NOT_AVAILABLE; db_route 'pooled'. dpa_document_id required uuid, soft reference (DATABASE.md), not verified.
- **Support-session window starts at approval** (AC-29.1 "approved for a set number of hours"): approved sets starts_at/ends_at; first in-session request flips approved -> active. Expiry job: approved|active past ends_at -> expired (approved -> expired is outside the documented machine), requested older than 24 h -> denied (decided_by NULL). Access stops at ends_at regardless of the job.
- **Decision rules**: decider must hold every scope permission over all markets (BR-SEC-05 analogue) -> 422 SUPPORT_SCOPE_NOT_HELD; requester region != tenant region needs region_approved (AC-31.1/TS-57); minutes <= requested; step-up + Idempotency-Key; no approval row (preparer would be a vendor user). factor_verified_at in the audit event.
- **Constants (E-ADR-10 / OQ-A8)**: SUPPORT_SESSION_MAX_MINUTES 480, REQUEST_TTL_MINUTES 1440, in support/sessions.ts (no config/setting key yet).
- **Ending**: vendor may end only active sessions (DB policy vendor_end); tenant (vendor_access.decide) ends approved or active. Both set ends_at = least(ends_at, now()).
- **Vendor log scope**: lifecycle and refusals in the vendor log; each in-session access only in the tenant log (it is the tenant-visible session log).
- **First-admin invitation** duplicates iam's issue+mail in ops/first-admin-invitation.ts (shortcut comment): iam exports no facade.

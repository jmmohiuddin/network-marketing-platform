| E-ADR-25 | CPL's inputs are guarded in the database (migrations 0030, 0031): triggers on IMP's `import_batch` (state into/out of `loaded`) and `import_mapping` (new version) retire snapshots in the same transaction (ready → outdated, computing → failed, audited), and `cpl_fact_*` rows can be inserted or deleted only while their batch is `mapped`. Every path that changes a snapshot's state takes `cpl_lock_inputs(tenant, market)` first, then the snapshot row, then the audit chain. In TypeScript CPL reads IMP only through its facades (`loadedBatches`, `tryLockLoads`, `batchDataQuality`) and TEN through `getSettingsVersion` | Module rule "cross-module access via facades only" (the trigger functions read `import_batch`/`import_mapping`); CPL still reads `market` by code directly, as IMP and IAM do (TEN has no market facade) | A load, a mapping save and a snapshot must agree atomically; a TS-only hook can be bypassed and invites lock-order deadlocks (review finding P6) | IMP/CPL move to an outbox event with equivalent atomicity |
| E-ADR-26 | API-05 keeps its grouped shape: `results[{report, period, period_kind, partial, notes, figures[], omitted[]}]`; figures carry `numerator`/`denominator` (counts, volumes or minor units, per `unit`), not `numerator_minor`/`denominator_minor`; the snapshot carries `mapping_id` (when one), `input_batch_ids`, `input_mapping_ids`, `input_mapping_versions`, and on GET /:id `input_data_quality[{batch_id, data_quality}]`.

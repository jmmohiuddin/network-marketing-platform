## 1. Design rules

| # | Rule | Reason |
|---|---|---|
| 1 | PostgreSQL 16 or later is the system of record (TRD-02) | Transactions for ledger and run commit; `ltree`; row-level security; range exclusion constraints; partitioning |
| 2 | Every tenant-scoped table has `tenant_id uuid NOT NULL` and a row-level security policy `tenant_id = current_setting('app.tenant_id')::uuid`; the application role cannot bypass RLS | Isolation in the data layer (SEC-01), independent of application code |
| 3 | Money is `bigint` minor units plus `currency char(3)`; rates are `numeric`; no `float`, `real` or `double precision` anywhere | BR-MNY-01 |
| 4 | History is kept by **effective dating** (`valid_from`, `valid_to`) and, for genealogy, **recorded time** (`recorded_at`, `superseded_at`); rows are closed, never overwritten | GAP-010 |
| 5 | Financial and result tables are **insert-only**: `UPDATE` and `DELETE` are revoked from the application role and blocked by trigger | BR-LED-02, replay |
| 6 | Primary keys are UUID version 7 (time-ordered) generated by the application | Index locality; safe to merge tenants across databases |
| 7 | Enumerations are `text` with `CHECK` constraints, listed under each table | Simple migrations |
| 8 | Standard columns on every table unless stated: `created_at timestamptz NOT NULL DEFAULT now()`, `created_by uuid` | Audit |
| 9 | Brand and market dimensions exist from the first release | GAP-095 (cheap now, costly later) |
| 10 | Sensitive values (tax identifiers, identity documents, bank details) are never stored in plain columns: ciphertext with per-tenant keys, or a document reference to the separate encrypted store, plus a masked display value | SEC-07 |
| 11 | Reserved words: the logical entities `order` and `case` are implemented as tables `sales_order` and `case_file` | SQL keyword clash |

## 2. Ownership and module boundaries

Each table has exactly one owner module. Other modules read through the owner's interface or through published read models; they never write to it. The *Owner module* column below is that assignment (it answers "database entities without clear ownership" in the traceability audit).
